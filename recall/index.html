The RECALL Method

A six-stage system for the other half of AI consulting: making a company's own documents answerable. Start with the questions the business actually needs answered, score the corpus that would have to answer them, and only then build a retrieval system — with a trust discount applied before anyone writes code.

Ask first. Score the corpus. Earn the right to build.

Where this sits

Two methods, one practice

LEVER and RECALL share a spine — a signed goal, a scoring instrument, honest gates, a sequenced plan, and a paid diagnostic that can recommend against building. They differ only in the unit of analysis. One routing question decides which applies.

LEVER

The unit is a decision

"We keep making this call badly." Recurring operational judgements with recorded outcomes. Output: a bespoke ML decision tool — a ranked worklist, a forecast, a flagged queue.

Binding constraint: are past decisions outcome-labelled?

or
RECALL

The unit is a question

"We can't find or trust what we already know." Recurring questions whose answers exist somewhere in the document estate. Output: a retrieval system people can rely on.

Binding constraint: is the corpus in a fit state to be retrieved from?

The routing question

"When this goes wrong, is it because someone chose badly, or because someone couldn't find out?" Ask it in the first meeting. The answer decides which method applies. Most sellers have one product and bend the problem to fit it; the question exists so that does not happen here.

The market gap

The cost is in the corpus, not the model

Access control, not the LLM, is repeatedly named the dominant cost driver. And across every pricing tier, the same sentence appears: messy source documents are the biggest schedule risk.

The thesis

A retrieval system cannot be better than the corpus it retrieves from — and nobody measures the corpus before quoting the build. That single omission is why these projects overrun, why demos impress and production disappoints, and why a four-week paid diagnostic is not an upsell but the cheapest insurance a buyer will ever be offered.

The system

Six stages, two commercial phases

R·E·C is the paid diagnostic and stands alone. A·L·L is the build. As in LEVER, the client can stop after C and still own something valuable — which is exactly why they say yes to C.

Phase 1 · The RECALL Diagnostic · 4–5 weeks
RStage 01

Requests The question taxonomy

Start with what people need to know, never with what documents exist. Every question gets a row in the Question Ledger: who asks it, how often, how long it currently takes to answer, and what it costs when the answer is late, wrong or never found.

  • Harvest real questions from search logs, helpdesk tickets, inbox archaeology and shadowing — not from a workshop where people invent tidy ones
  • Cluster into question classes; a system serves classes, not individual queries
  • Time the current answer path end to end, including the "I'll ask Sarah" hop that never appears in a process map
  • Separate questions from reports. Most stated "search needs" are dashboards in disguise.
Output: The Question Ledger — 15–30 question classes with owner, annual volume, current time-to-answer and cost of failure.
EStage 02

Estate Corpus census

Find every place an answer could live, and who governs it. This is where projects quietly die: the authoritative version is in a mailbox, a shared drive nobody admits to, or a system whose owner left.

  • Inventory repositories, volumes, formats, growth rate and access model
  • Identify the system of record per question class — and where a contradicting copy lives
  • Map governance early: PII, retention, confidentiality tiers, who may see what. Access control is the single biggest build cost, so it is scoped here, not discovered later.
  • Flag anything that must never be retrievable. This list is worth the fee on its own.
Output: Corpus census with an authority map and a governance matrix per repository.
CStage 03

Condition Score the corpus, cost the answer

Sample and score. This is the stage nobody else sells, and it is the reason the build quote is safe when everyone else's is a guess.

  • Stratified sample of each repository — 100–300 documents is usually enough to be decisive
  • Score the six dimensions of the Corpus Condition Index
  • Type every question class on the Retrievability Ladder — and name the ones that are not retrieval problems at all
  • Build the gold set: 50–100 real questions with verified answers and source spans
  • Run the Answerability Equation; sequence remediation before build
Output: Corpus Condition Index, Retrievability map, gold set v1, architecture blueprint, A£ and AQ per question class, sequenced plan. This is the artefact the client keeps.
Phase 2 · The RECALL Build · 8–14 weeks
AStage 04

Architect Chunking, metadata, retrieval

The architecture is prescribed by the question archetype, not by fashion. Metadata is designed before chunking, because chunking without metadata is how you build something that retrieves confidently and wrongly.

  • Metadata schema first: source, authority tier, effective date, supersedes, confidentiality, entity tags. Budget for this properly — practitioners consistently report it consuming around 40% of build time.
  • Chunking to match the archetype: hierarchy-preserving for procedures, parent-document for synthesis, small + filtered for lookup. Fixed-size chunks alone are a demo technique.
  • Hybrid retrieval by default: lexical and dense together, then rerank. Pure vector search fails exactly where clients test it — names, codes, clause numbers.
  • Access control in the retrieval path, never in the interface. Filter before you rank, or you have built a data breach with a chat window.
Output: Metadata schema, chunking policy per archetype, retrieval design, and the permission model — all reviewed against the gold set before build.
LStage 05

Loop Evaluate before you ship

The gold set exists from stage C, so evaluation is not an afterthought bolted on when someone complains — it is the acceptance criterion the contract is written against.

  • Measure retrieval and answer quality separately. Most "the AI is wrong" complaints are retrieval failures wearing a generation costume.
  • Regression-test every change against the gold set. No green run, no deploy.
  • Ship the honest baseline first — keyword search with good metadata filters. If the full stack cannot beat it on the gold set, say so.
  • Instrument abstention. A system that says "I don't know" is worth more than one that is 90% right and unmarked.
Output: Evaluation harness, gold-set scores, an abstention policy and a published accuracy claim you can actually defend.
LStage 06

Live Deploy, secure, monitor

Adoption is a trust problem here, not a training problem. People abandon a retrieval system the third time it answers confidently and wrongly, and they never come back.

  • Every answer carries its sources, dates and authority tier. Citation is a product feature, not a nicety.
  • Immutable audit log of every retrieval call where the sector requires it
  • Monitor corpus drift: new documents degrade a tuned system silently, and the first sign is usually a user quietly going back to asking Sarah
  • Quarterly gold-set re-run tied to a published quality report
Output: Live system, audit trail, quality report — and the drift curve that justifies the retainer honestly.
Instrument one

The Corpus Condition Index

Six dimensions, 0–5 each, scored from a stratified sample. Total 0–30, then normalised to 0–1 as the C term in the equation. This is the instrument that turns "your documents are a mess" — a sentence that sounds like blame and closes the conversation — into a number the client can act on.

01

Extractability

Can clean text be got out at all? Scans, image-only PDFs, tables that collapse into soup, multi-column layouts, handwriting.

Score 0–1 → nothing downstream works. Remediation is not optional.
02

Structure

Is there hierarchy to preserve — headings, clause numbering, sections? Structure is what lets chunking keep meaning instead of slicing it.

Low structure caps synthesis and procedural questions permanently.
03

Uniqueness

Duplication and near-duplication. The classic finding: half a repository is the same documents with trivial format differences.

Duplicates don't just waste space — they split retrieval confidence and surface the wrong version.
04

Currency

How much is stale or superseded — and crucially, can you tell? An undated corpus cannot answer any time-sensitive question safely.

This is the dimension that creates confidently wrong answers.
05

Provenance

Do you know source, author, version, effective date and authority tier? Without provenance you cannot cite, and without citation nobody trusts it.

No provenance → no defensible answer in any regulated setting.
06

Governance

Access rules, PII, confidentiality tiers, retention obligations, and the material that must never be retrievable at all.

Scoped here or it becomes the largest unplanned cost in the build.
Why it is worth the diagnostic fee on its own

A CCI is a reusable asset for the client even if they never build anything. It tells them which repositories to consolidate, what their retention exposure is, and where the authoritative version of the truth actually lives. Some clients remediate and postpone the system — and that is a good outcome.

Instrument two

The Retrievability Ladder

Seven question archetypes. The archetype prescribes the architecture — and, more valuably, tells you when the honest answer is this is not a retrieval problem. Three of the seven are not. Naming them is the most credible thing you will do all engagement.

ArchetypeExample question ArchitectureHonest note
Lookup"What's the notice period in the Acme contract?" Small chunks, hybrid lexical + dense, hard metadata filters, rerank. The easiest win. Retrievable. Start here — it builds trust cheaply.
Procedural"How do I onboard a supplier in France?" Hierarchy-preserving chunking; a step must never be split. Parent-document retrieval. Retrievable, but fixed-size chunking destroys it.
Compare"How does this policy differ from the 2024 version?" Multi-document retrieval with version metadata, then structured diff — not free-text generation. Retrievable only if Currency and Provenance score well.
Trace"What changed, when, and who approved it?" Temporal metadata, versioned corpus, event-style indexing. An archive-design problem before it is a retrieval one.
Synthesise"What's our overall position on data residency?" Hierarchical retrieval, map-reduce summarisation, mandatory citation, forced abstention on thin evidence. Highest hallucination exposure. Apply a heavy Trust Discount.
Aggregate"How many contracts have terms over 90 days?" Not RAG. Structured extraction into a table, then SQL. Retrieval cannot count and will confidently guess. The single most common doomed request. Say no early and propose extraction instead.
Judgement"Should we accept this clause?" Not RAG alone. Retrieve, cite and assemble the evidence — then a human decides. Never generate the conclusion. If a client insists, this is a professional-indemnity conversation, not a build.

Two sentences from the first meeting

"About a third of what you've described isn't a search problem — it's a counting problem, and search will answer it confidently and wrongly. Let me show you which ones."

Nobody selling a RAG build says this.

Instrument three

The Answerability Equation

Deliberately the same shape as LEVER's — one mental model across both methods — with one term that only exists here. Output in pounds per year, per question class.

A£  =  N × Δ × a  ×  (C × R × A)  ×  (1 − H)

Value of the answer × Answerability × Trust discount

N

Volume

How many times a year this question class is asked. From search logs and ticket systems, never from a workshop.

Δ

Cost per ask

Time to answer at loaded cost, plus rework, plus duplicated effort, plus the cost of deciding without the answer.

a

Retrieval-addressable share

0–1. The fraction of Δ that finding could remove. If the answer genuinely does not exist anywhere, no retrieval system creates it — and pretending otherwise is how these projects earn their reputation.

C·R·A

Answerability

Corpus condition × retrievability of the archetype × adoption and trust feasibility. Multiplied, not averaged — any zero correctly kills the whole thing.

H

The Trust Discount

0–1. The share of value destroyed by an unacceptable wrong-answer rate in this domain. The term that exists here and nowhere else.

AQ

Answerability Quotient

A£ ÷ (build cost + year-one run cost). The ranking number. Build if AQ ≥ 3.

!

Why H changes everything

In a high-stakes domain, a system that is right 90% of the time can be worth less than nothing — because every answer must now be verified by hand, so you have added a step rather than removed one. H is what stops that system being built. Set H high for clinical, legal-advice, regulatory and financial-promotion contexts, low where a wrong answer is merely annoying and obvious.

The gates

Five ways the diagnostic says no

Checked in this order, before AQ. A large A£ sitting on an unfit corpus is a mirage, and AQ will happily endorse it.

C < 0.40 → Remediate first.

The corpus cannot support retrieval yet. Run a corpus remediation project — dedup, OCR, dating, metadata backfill — then revisit. This is the honest recommendation, and it is real work, not a delay.

Archetype is Aggregate or Compute → Extract, don't retrieve.

Structured extraction into a table plus SQL. Retrieval cannot count. This gate alone saves one doomed build a year.

H > 0.50 → Assist, don't answer.

Build retrieve-and-cite for a human reviewer. Never generate the conclusion. The scope shrinks, the fee shrinks, and the answer stays defensible.

No gold set → no build.

Fifty to a hundred real questions with verified answers and source spans, before a line of code. Without it there is no acceptance criterion, fixed-fee is unsafe for both sides, and "is it working?" becomes a matter of opinion forever.

AQ < 3 → don't build.

Below three times year-one cost the risk premium on a bespoke retrieval system is not earned. Narrow to a single question class, or walk.
